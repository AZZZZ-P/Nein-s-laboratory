# 逐词对照数据格式（data.json）

阅读器只吃一个 JSON。生成 HTML 时用 `scripts/build_reader.py` 校验并注入模板，
不要手写 HTML、也不要改模板里的 `__DATA__` 以外的部分。

## 顶层结构

```json
{
  "meta": {
    "titleEn": "原文标题",
    "titleZh": "中文标题",
    "slug": "paper-slug",
    "byline": "作者 · 期刊/年份 · 说明",
    "cite": ["汇总 Markdown 里引用的原文行，可多条"],
    "notesFile": "自定义_读书感悟"
  },
  "sections": [
    { "id": "1. 引言",
      "head": { "zh": "1. 引言", "en": "1. Introduction", "t": ["引言"] },
      "paras": [
        { "key": "p1", "kind": "para", "title": false,
          "sents": [ { "en": "...", "zh": "...", "t": [["word", "释义"], ["phrase", "释义"]] } ] }
      ] }
  ]
}
```

- `meta.slug` 决定 localStorage 笔记键（`qoder.<slug>.notes.v1`）和下载文件名前缀；
  同一篇文章换 slug 会丢已有笔记，保持稳定。
- `sections[]` 按文章逻辑分节，每节一个 `h2` 标题与一个顶部导航按钮。
- `paras[].key` 在节内唯一（`p1`、`fn1`、`meta1`…），用于把句子归回同一段落。
- `paras[].kind`：
  - `para` 正文（左栏合成 `<p>`，句间空格相连）；
  - `footnote` 脚注（渲染成虚线块，`label` 写成「脚注 2」）；
  - `meta` 题录/作者单位等附属信息（虚线小字块）。
- `paras[].title = true`：该段用大号加粗排版（论文标题放在第一节时用它）。
- 句子里的空格、斜体等排版差异不用管，`en` 只需保证词序与原文一致。

## 逐词数组 t 的硬规则

`t` 是 `[词面, 释义]` 的数组，阅读器靠它在左栏高亮，所以：

1. **顺序必须与原文从左到右一致。** 释义写在词面后面，一条也不能提前。
   违反时 `--check` 报 `BACKWARD`（回溯匹配），高亮游标会被带偏。
2. **词面必须能在句中找到。** 定位方式是「压缩索引」：句子和词面都只保留 Unicode
   字母与数字并转小写，再子串查找。所以
   `so-called` / `vis-à-vis` / `and/or` / `（2000）` / 全角括号 都能正常命中，
   但拼写不一致（`behaviour` vs `behavior`、被吞掉的词）会报 `HARD MISS`。
3. **一条可以是一个词组**（`["the minimum necessary", "最低限度的要求"]`），
   但词组内部不能再夹后面的单词，否则后面那些词会被前一条「吃掉」。
   长限定结构（`the minimum necessary that is set by law`）要拆成
   `the minimum necessary` / `that` / `is set by law` 三条。
4. **每个词条的释义非空**，且除纯数字/纯符号外应含中文，否则报 `EMPTY GLOSS` / `NO CJK GLOSS`。
5. **一条一个词面**。不要把三个词挤在一条里用 `/` 分隔：
   `["policy", "政策 / 利益集团"]` 会让第二个词无法定位。

## 常见的「不干净」来源与修法

写数据时最容易从 Markdown 稿件或 PDF 抽取里带进这几类噪声：

| 症状 | 原因 | 修法 |
| --- | --- | --- |
| `HARD MISS`：词面尾部多了英文 | 注释里的英文例句被粘到词面上（`"set 设置 (set up 建立)"`） | 从右往左收缩词面，直到能定位，收缩掉的部分并进释义 |
| `HARD MISS`：词面是 `X X` 或带空格拉开 | PDF 抽取的字距/重复 | 去重或按原样写连字符形式 |
| 漏了真实单词 | 释义里用 `/` 串了后续词条（`"n. 政策 / 利益集团"`） | 按 `\s*/\s+|/\s+` 拆，前半段的英文字母开头部分（`LEAD` 正则：`^[A-Za-z0-9'’()\[\].,&\-–— ]+`）还原成独立词条，其余留在上一条释义里 |
| `BACKWARD`：多出来的伪词条 | 多词词组内部又给其中一两个词单独加注 | 若本条词面恰好是前一条词面里连续的几个词 → 删掉本条；**必须在收缩之前删**，否则游标已被带偏 |
| 空释义 + 下一条被误判 | `("2000")` 这类纯符号条目 | 把它的词面并进上一条释义（`(2000) 2000 年`） |
| 假命中：`February 2` 定位成功 | 压缩索引丢空格，`february2` ⊂ `february2023` | 显式改写：`February 2` → `February` + `2 月`。凡是「数字/月份粘连」的可疑命中都要人工过一遍 |
| 悬挂连字符 `vis-` + `à-vis 相对于` | PDF 换行断词 | 合并成 `vis-à-vis`，且只在合并后能定位、且剩余释义含非 ASCII 时合并 |
| `and` / `or` 两条却原文是 `and/or` | 逐词表按空格切 | 合成一条 `and / or` |

修复要做成**可重跑的脚本**（读 `data.bak.json` → 写 `data.json`），别直接在成品上反复改，
否则分不清哪一步弄坏了什么。每轮跑完看四个计数：`miss` / `backward` / `empty_gloss` / `tokens`，
前三者必须为 0。
